# 範例程式：交通安全小達人

這是《PBL 專題：設計我的多媒體測驗系統》的參考程式。PBL 文件裡填寫的每一個部分，在 `sketch.js` 最上面的設定區都有對應的資料，讓你看到「設計文件」怎麼變成「程式」。

## 執行方式

1. 用 VS Code 開啟這個資料夾。
2. 在 `index.html` 上按右鍵，選「Open with Live Server」。
3. 瀏覽器會開啟測驗。按 `F12` 打開 Console，作答結束後可以看到測試紀錄表。

```
交通安全小達人/
├── index.html
├── style.css
├── sketch.js          ← 全部程式（設定區在最上面）
├── libraries/
│   ├── p5.min.js
│   └── p5.sound.min.js
└── media/             ← 放你自己的圖片、聲音、影片（本範例不需要）
```

## PBL 文件與程式的對照

| PBL 章節 | 你在文件裡寫的 | 程式裡的位置 | 本範例的內容 |
|---|---|---|---|
| 1-1 使用者 | 使用者是誰、在哪裡使用 | `PROJECT.users` | 國小三年級學生，課堂上用平板或電腦，一次約 5 分鐘 |
| 1-2 學習目標 | 「能＋動詞」的目標 | `PROJECT.goals` | ① 看懂號誌 ② 分辨警示聲音 ③ 說出安全做法 |
| 1-5 需求清單 | Must／Should／Could | `FEATURES` 的開關 | Must 的功能預設開啟 |
| 2-2 功能規格 | F1～F7 | `FEATURES.F1_startScreen` 等 | 見下方功能表 |
| 2-3 流程圖 | 開始 → 作答 → 回饋 → 成績 | `screen` 變數 | `"start"` → `"quiz"` → `"result"` |
| 2-4 視覺風格 | 主色、輔色、答對答錯顏色 | `STYLE` | 安全綠 `#1F7A4D`、警示黃 `#F2B705` |
| 2-5 題目設計 | 題型、題目、選項、答案、解說、對應目標 | `QUESTIONS` | 8 題：4 題動畫、4 題聲音 |
| 2-6 素材清單 | 來源與授權 | `MEDIA_CREDITS` | 全部程式自製 |
| 3-5 測試紀錄 | 功能測試結果 | `printTestLog()` | 作答結束時在 Console 印出表格 |
| 4-3 成果 | 學習目標達成情形 | 成績頁 | 依學習目標統計答對比例 |

## 功能規格（PBL 2-2）

| 編號 | 功能 | 使用者看到什麼 | 程式開關 |
|---|---|---|---|
| F1 | 開始畫面 | 標題、動畫預覽、學習目標、開始按鈕 | `F1_startScreen` |
| F2 | 選項打亂 | 每次作答選項順序不同 | `F2_shuffleOptions` |
| F3 | 聲音自動播放 | 進入聲音題時自動播放一次，點畫面可重聽 | `F3_autoPlaySound` |
| F4 | 立即回饋與解說 | 答對變綠、答錯變紅，並顯示原因 | `F4_explain` |
| F5 | 計時 | 上方顯示作答時間，成績頁顯示用時 | `F5_timer` |
| F6 | 錯題再練 | 成績頁出現「錯題再練」，只重做答錯的題目 | `F6_retryWrong` |
| F7 | 鍵盤操作 | 1～4 選答案、Enter 下一題、P 重聽 | `F7_keyboard` |

把開關改成 `false`，就能看到少了這個功能時，使用體驗有什麼不同。

## 題目資料怎麼寫（PBL 2-5）

```javascript
{ id: "Q2",                  // 題號，測試紀錄會用到
  type: "sound",             // 題型：anim / sound / image / audio / video
  sound: "siren",            // 內建聲音名稱（自備媒體改用 src: "media/檔名"）
  goal: 2,                   // 對應第幾個學習目標
  q: "聽到這個聲音，路上的車子和行人應該怎麼做？",
  options: ["讓路給救護車", "跟在救護車後面", "停在路中間看", "按喇叭回應"],
  answer: "讓路給救護車",     // 要和某個選項一模一樣
  explain: "這是救護車的警笛聲。車子要靠邊讓路……" }
```

**寫好選項的小技巧**：錯誤選項要「看起來有可能」，最好是使用者常犯的錯（例如「趁柵欄還沒放下趕快跑過去」），這樣答錯時的解說才有教育意義。

## 改成你自己的專題

| 步驟 | 要改的地方 | 說明 |
|---|---|---|
| 1 | `PROJECT` | 換成你的標題、使用者、學習目標（2～4 個） |
| 2 | `STYLE` | 換成你在 PBL 2-4 選的配色 |
| 3 | `QUESTIONS` | 換成你在 PBL 2-5 設計的題目，記得每題寫 `goal` 和 `explain` |
| 4 | `media/` | 放入你的圖片、聲音、影片，題目改用 `type: "image"`、`"audio"`、`"video"` 加 `src` |
| 5 | `MEDIA_CREDITS` | 寫上每個素材的來源與授權 |
| 6 | `FEATURES` | 依你的需求清單開關功能 |
| 進階 | `ANIMS`、`SOUNDS` | 仿照範例的函式，寫自己的程式動畫或合成聲音 |

> 只換設定區就能得到一個可以用的測驗。想要更有特色，再請 AI 協助你新增功能，並把過程記錄在 PBL 文件的「AI 協作紀錄」。

## 測試方法（PBL 3-5）

- **功能測試**：故意答錯幾題，確認錯題再練只出現答錯的題目。
- **Console 紀錄**：按 `F12` 打開 Console，作答結束會印出每題的選擇、對錯和作答秒數，可以貼到 PBL 的測試表。
- **裝置測試**：在 Chrome 開發人員工具切換手機模式（`Ctrl + Shift + M`），檢查直向畫面的按鈕和文字。
- **自備媒體**：檔名打錯時，畫面會顯示「找不到圖片：檔名」，方便除錯。
